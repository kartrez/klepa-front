Часть 4 · Доверяй, но проверяй · Урок 7

Ловим ошибки агента автоматически: слои проверок, бюджеты, петли и выдуманные методы

Агент ошибается не так, как человек: быстро, уверенно и иногда с отчётом «всё готово». Разберём, какие ошибки бывают и как встроить в harness проверки, которые ловят их без вас.

~50 минут 4 интерактива 3D-фильм и 11 вопросов Примеры: JS · TS · PHP · Python

После урока вы сможете

  • узнавать семь типовых ошибок агента в логе его работы;
  • собрать слои защиты: проверки кодом, бюджеты, трейсы и человек на воротах;
  • узнавать петлю и выдуманные методы и ставить на них автоматические проверки;
  • подключить линтер и тесты к агенту через хуки.

Конвейер с ОТК

2 Объяснение

От простого к сложному

Уровень 1 · Суть

Каждый шаг проверяет код, у каждой задачи есть бюджет

Человек ошибается медленно и обычно сомневается. Агент делает десятки правок в минуту и звучит одинаково уверенно, когда прав и когда нет (урок 1). Читать всё руками невозможно. Поэтому правило простое:

  • после каждого действия агента его результат проверяет код: линтер, типы, тесты;
  • у каждой задачи есть лимиты: шаги, токены, время;
  • каждый шаг записывается, чтобы потом разобраться.
ГлавноеНе верьте отчёту агента «всё готово». Верьте результатам проверок, которые агент не может подделать.
Уровень 2 · Детали

Семь типовых ошибок и чем их ловить

Выдуманный APIВызов метода или импорт, которого нет: Money::fromFloatSafe().Ловят: статанализ (phpstan, tsc, mypy), тесты.
Неверная логикаКод работает, но считает не то: скидка не применяется.Ловят: тесты, особенно написанные до правки.
Правки вне задачи«Заодно поправил» конфиг безопасности или соседний модуль.Ловят: проверка diff — какие файлы можно трогать.
Ослабленный тестТест красный, и агент поменял ожидание в тесте, а не код.Ловят: запрет правки tests/ без явного разрешения, ревью.
ПетляОдна и та же команда раз за разом, с тем же результатом.Ловят: детектор повторов, лимит шагов.
ПерерасходЗадача на 50 тысяч токенов съела 2 миллиона.Ловят: бюджет токенов и денег на задачу.
Ложный отчёт«Готово, тесты проходят», а тесты не запускались.Ловят: Stop-хук, который сам запускает тесты.

Слои ставят от дешёвых к дорогим. Линтер стоит секунды и ловит много. Человек стоит дорого, поэтому он смотрит только то, что прошло все автоматические слои, и только в важных точках: слияние в main, миграция, выкладка.

Как слои работают вместе, видно в фильме — 50 секунд. Остановите его, перемотайте, поверните сцену и посмотрите вдоль пути ошибки.

Уровень 3 · Усложнение

Как встроить контроль в harness

  • PostToolUse-хук после каждой правки файла запускает линтер для этого файла. Ошибки уходят модели сразу (код выхода 2 и текст в stderr), и она исправляет их на следующем шаге, а не через час в CI.
  • Stop-хук не даёт агенту закончить, пока тесты красные. Ложный отчёт «всё готово» становится невозможным.
  • PreToolUse-хук запрещает правку защищённых файлов: тестов, конфигов линтера, CI. Иначе агент «починит» проверку, а не код.
  • Оркестратор (урок 4) держит бюджет: максимум шагов, токенов и времени. Превысил — остановка с отчётом, а не тихий счёт на сотни долларов.
  • Трейс: каждый шаг пишется в JSON-лог: номер, инструмент, аргументы, токены, время, результат. По нему находят петли, дорогие шаги и причины аварий.

Метрики процесса, которые стоит считать: стоимость решённой задачи, доля задач с вмешательством человека, сколько брака дошло до ревью и до прода, сколько раз сработал каждый слой. Если слой не сработал ни разу за месяц — проверьте, работает ли он вообще.

ЛовушкаНе делайте единственным контролем «вторую модель, которая проверит первую». Это полезный слой (урок 8), но у проверяющей модели те же слабости. Основа — детерминированные проверки, которые дают один и тот же ответ на один и тот же код.
Хуки контроля в коде — линтер после правки, тесты перед финишем 
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "node .claude/hooks/lint-after-edit.js" }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "python3 .claude/hooks/tests-before-stop.py" }] }
    ]
  }
}
// .claude/hooks/lint-after-edit.js — PostToolUse: ESLint для правленого файла
import { execFileSync } from "node:child_process";

let raw = "";
process.stdin.on("data", (c) => (raw += c));
process.stdin.on("end", () => {
  const file = JSON.parse(raw).tool_input?.file_path ?? "";
  if (!/\.(ts|js)$/.test(file)) process.exit(0);
  try {
    execFileSync("npx", ["eslint", "--max-warnings=0", file], { encoding: "utf8" });
    process.exit(0);
  } catch (e) {
    // код 2: ошибки уйдут модели, она исправит их на следующем шаге
    process.stderr.write(`ESLint нашёл проблемы в ${file}:\n${e.stdout}`);
    process.exit(2);
  }
});
#!/usr/bin/env php
<?php
// .claude/hooks/lint-after-edit.php — PostToolUse: phpstan для правленого файла
$event = json_decode(stream_get_contents(STDIN), true, flags: JSON_THROW_ON_ERROR);
$file = $event['tool_input']['file_path'] ?? '';
if (!str_ends_with($file, '.php')) {
    exit(0);
}
exec('vendor/bin/phpstan analyse --no-progress --error-format=raw ' . escapeshellarg($file) . ' 2>&1', $out, $code);
if ($code !== 0) {
    fwrite(STDERR, "phpstan нашёл ошибки в $file:\n" . implode("\n", $out));
    exit(2);
}
exit(0);
#!/usr/bin/env python3
# .claude/hooks/tests-before-stop.py — Stop: не отпускать агента с красными тестами
import json
import subprocess
import sys

event = json.load(sys.stdin)
# Если агент уже продолжает работу из-за этого хука, не держим его вечно
if event.get("stop_hook_active"):
    sys.exit(0)

proc = subprocess.run(["pytest", "-q", "-x"], capture_output=True, text=True)
if proc.returncode != 0:
    tail = (proc.stdout + proc.stderr)[-3000:]
    print("Тесты красные, задачу нельзя считать готовой:\n" + tail, file=sys.stderr)
    sys.exit(2)
sys.exit(0)
// trace.ts — простой трейс шагов агента в JSON Lines
import { appendFileSync } from "node:fs";

interface TraceStep {
  task: string;
  step: number;
  tool: string;
  input: unknown;
  inputTokens: number;
  outputTokens: number;
  ms: number;
  ok: boolean;
}

export function trace(s: TraceStep): void {
  // одна строка — один шаг: легко грепать, считать и грузить в Grafana/Loki
  appendFileSync("var/agent-trace.jsonl", JSON.stringify({ at: new Date().toISOString(), ...s }) + "\n");
}

        4 Тесты
        
    Проверьте себя
    
        
    Код писать не нужно. Где верный ответ один, он засчитывается по клику. Где написано «Отметьте все верные ответы», выберите все подходящие и нажмите «Проверить»: зачёт только при точном совпадении. Ответы сохраняются в браузере.
    
      
    

      
    
        
    Вопросы по уроку
    
        
    
          
    Агент поменял ожидаемое значение в тесте с 90 на 100, и тест позеленел. Как ловить такое автоматически?
    
          
    
            
            
            
          
    
          
    Просьба — мягкое правило. Защищённые файлы — жёсткое: агент получит отказ и будет вынужден чинить код, а не проверку.
    
        
    
        
    
          
    Что быстрее и дешевле всего ловит вызов несуществующего метода?
    
          
    
            
            
            
          
    
          
    Phpstan, tsc или mypy находят такие ошибки за секунды и всегда одинаково. Через PostToolUse-хук агент узнаёт об ошибке на следующем же шаге.
    
        
    
        
    
          
    Агент сорок раз подряд запускает одну и ту же команду. Что должно сработать?
    
          
    
            
            
            
          
    
          
    Каждый повтор отправляет модели всю историю заново, поэтому петля дорожает быстрее, чем линейно (урок 1). Стоп-кран должен быть кодом.
    
        
    
        
    
          
    Почему нельзя верить итоговому сообщению агента «всё готово, тесты проходят»?
    
          
    
            
            
            
          
    
          
    Модель пишет правдоподобный отчёт, даже если тесты не запускались. Stop-хук, который сам запускает тесты, превращает отчёт в факт.
    
        
    
        
    
          
    Какие шаги агента похожи на петлю?
    
          
    
            
            
            
            
          
    
          
    Детектор петли ищет повторы одного вызова и пары вызовов. Аргументы сравнивают после сортировки ключей, иначе петля спрячется за другим порядком. Чтение, правка и тесты — нормальный рабочий цикл, а не петля.
    
        
    
        
    
          
    В индексе проекта у класса Money есть методы fromFloat, greaterThan, percent, minus, toCents. Какие вызовы в правке агента выдуманы?
    
          
    
            
            
            
            
          
    
          
    Как в интерактиве 4: каждый вызов сверяют с индексом символов. fromFloatSafe и applyDiscountMagic в индексе нет — это выдумка модели. Статанализ находит такое за секунды, ещё до тестов.
    
        
    
        
    
          
    Что верно про хуки контроля?
    
          
    
            
            
            
            
          
    
          
    PreToolUse срабатывает до действия, поэтому им запрещают опасное: правку tests/, CI, конфигов проверок. Тесты после каждого шага гонять дорого — их запускает Stop перед финишем, а после правки хватает быстрого линтера.
    
        
    
        
    
          
    Почему слои защиты ставят от дешёвых к дорогим?
    
          
    
            
            
            
          
    
          
    У каждого слоя есть дыры, как в фильме про сыр. Дешёвые слои снимают массовый брак, дорогие ловят редкое. Без дешёвых слоёв человек утонет в ошибках, которые нашёл бы линтер.
    
        
    
        
    
          
    Что стоит записывать в трейс каждого шага агента?
    
          
    
            
            
            
            
          
    
          
    По трейсу находят петли, самые дорогие шаги и причины аварий. Итоговое сообщение — тоже генерация текста: по нему не видно, что агент делал на самом деле.
    
        
    
        
    
          
    В фильме ошибка «логика без теста» прошла четыре слоя подряд. Что это значит?
    
          
    
            
            
            
          
    
          
    Каждый слой ловит своё и пропускает остальное. Опасно, когда дыры совпадают. Лечится не удалением слоёв, а ещё одним слоем там, где у прошлых дыра.
    
        
    
        
    
          
    Можно ли сделать единственным контролем вторую модель, которая проверяет первую?
    
          
    
            
            
            
          
    
          
    Проверяющая модель тоже может уверенно ошибиться. Линтер, типы и тесты дают один и тот же ответ на один и тот же код — на них и держится защита. Модель-судья полезна сверху (урок 8).
