Часть 2 · Агент в вашем проекте · Урок 2

Агент — это цикл: инструменты, правила, скилы и субагенты

Модель умеет только писать текст. Агентом её делает цикл вокруг: программа отправляет модели историю и список инструментов, выполняет то, что модель попросила, и возвращает результат. Разберём этот цикл по строчкам кода, а потом всё, что его настраивает: правила, разрешения, скилы и субагенты.

~50 минут 3D-фильм с кодом 3 интерактива 14 вопросов Примеры: JS · TS · PHP · Python

После урока вы сможете

  • разобрать цикл агента по строкам кода: кто думает, кто выполняет и когда цикл заканчивается;
  • написать свой цикл, который не падает на ошибке инструмента и не крутится вечно;
  • написать короткий и полезный файл правил проекта (CLAUDE.md или AGENTS.md);
  • отличить мягкое правило от жёсткого запрета и настроить разрешения;
  • понять, когда нужен скил, а когда субагент, и как они экономят контекст.

Всё это вместе — harness («упряжь»). Одна и та же модель в хорошем и плохом harness работает как два разных инженера.

2 Объяснение

От простого к сложному

Уровень 1 · Суть

Агент — это модель в цикле с инструментами

Модель ничего не запускает сама. Она только пишет запрос: «вызови инструмент run_tests». Такой запрос называют tool_use. Программа вокруг модели (harness) выполняет его, дописывает результат в историю и снова зовёт модель.

Один круг цикла:

  1. Программа отправляет модели всю историю и описания инструментов.
  2. Модель отвечает текстом или просьбой вызвать инструмент.
  3. Программа проверяет права и выполняет инструмент.
  4. Результат (tool_result) дописывается в историю, и круг начинается снова.

Круги идут, пока модель не ответит со stop_reason end_turn: «я закончила». Цикл и инструменты — ваши, рассуждение — за моделью.

messages = [задача]
while (true) {

  результат = выполнить(ответ.tool_use)   // harness делает
  messages.push(ответ, результат)         // история растёт
}

async function runAgent(task) {
  const messages = [{ role: "user", content: task }];          // история — всё, что знает агент

  for (let step = 0; step < 20; step++) {                      // лимит шагов
    const res = await callModel({ model: "claude-opus-5-5", max_tokens: 4096, tools, messages });
    messages.push({ role: "assistant", content: res.content });  // ответ целиком

    if (res.stop_reason === "end_turn") {                      // модель закончила
      return res.content.filter(b => b.type === "text").map(b => b.text).join("\n");
    }
    if (res.stop_reason !== "tool_use") {                      // max_tokens, refusal…
      throw new Error(`Цикл остановлен: ${res.stop_reason}`);
    }

    const results = [];
    for (const block of res.content.filter(b => b.type === "tool_use")) {
      try {
        if (!allowed(block)) throw new Error("Запрещено правилами проекта");  // проверка прав
        const run = handlers[block.name];
        if (!run) throw new Error(`Нет инструмента ${block.name}`);
        results.push({ type: "tool_result", tool_use_id: block.id, content: await run(block.input) });
      } catch (e) {
        results.push({ type: "tool_result", tool_use_id: block.id, content: e.message, is_error: true });
      }
    }
    messages.push({ role: "user", content: results });         // все результаты — одним сообщением
  }
  throw new Error("Лимит шагов: агент зациклился");
}

    Уровень 2 · Детали

    Из чего состоит harness

    Возьмём Claude Code (агент Anthropic для терминала). У Codex, Cursor и других агентов те же части, только файлы называются иначе.

    • Системный промпт — базовые инструкции агента. Его пишет разработчик инструмента, вы его обычно не трогаете.
    • Файл правил проекта — CLAUDE.md или AGENTS.md в корне репозитория. Агент читает его в начале каждой сессии. Там команды сборки и тестов, структура, договорённости, запреты.
    • Инструменты (tools) — чтение и правка файлов, поиск, запуск команд. Каждый описан именем, описанием и схемой аргументов.
    • Разрешения (permissions) — в .claude/settings.json. Список allow: можно без вопросов. Список deny: нельзя никогда. Остальное агент спрашивает у вас.
    • Скилы (skills) — папка .claude/skills/<имя>/ с файлом SKILL.md. Это инструкция под типовую задачу: «как выпустить релиз», «как писать миграцию».
    • Субагенты (subagents) — файлы .claude/agents/<имя>.md. Отдельный агент со своим окном контекста и своим набором инструментов.
    • Управление контекстом — сжатие старой истории, кэш, вынос тяжёлой работы в субагентов.
    Мягкое и жёсткое правилоСтрока в CLAUDE.md «не читай .env» — это просьба к модели. Обычно её выполняют, но гарантии нет. Правило deny в settings.json или хук (урок 4) — это код. Его выполняет harness, и модель не может его обойти. Важное — делайте жёстким.

    Уровень 3 · Усложнение

    Контекст — главный бюджет harness

    Всё, что вы добавляете в harness, конкурирует за одно окно контекста (урок 1). Поэтому хороший harness устроен по принципу прогрессивного раскрытия: в окне лежит минимум, подробности подгружаются по требованию.

    • Скил стоит в контексте ~30–100 токенов (имя и описание), пока не нужен. Если бы все инструкции лежали в CLAUDE.md, каждая сессия платила бы за все сразу.
    • Субагент читает 30 файлов в своём окне, а в основное возвращает отчёт на полстраницы. Основной агент остаётся «свежим».
    • Описание скила или субагента — это то, по чему агент решает, звать ли его. Плохое описание — скил никогда не сработает.

    Правила честного цикла. Их легко нарушить, когда пишешь цикл сам. Все пять видно в коде под фильмом.

    • Ответ модели — в историю целиком. Не только текст, а весь content: с tool_use и блоками рассуждения. Потеряете tool_use — следующий запрос получит ошибку 400: результату не к чему привязаться.
    • На каждый tool_use — свой tool_result с тем же tool_use_id. Модель может попросить несколько инструментов в одном ответе. Все их результаты отправляют одним сообщением user: иначе модель со временем перестаёт просить параллельно.
    • Ошибка инструмента — тоже результат. Ловите исключение и возвращайте текст ошибки с is_error: true. Модель прочитает его и попробует иначе, а программа не упадёт.
    • stop_reason разбирают целиком. end_turn — конец, tool_use — работаем дальше. max_tokens или refusal — остановиться: повтор того же запроса даст тот же ответ и съест деньги.
    • Лимит шагов. Модель может просить одно и то же бесконечно. Счётчик в цикле остановит её на 20-м круге.

    Типичные ошибки конфигурации:

    • CLAUDE.md на 1000 строк: важное тонет, токены горят на каждой сессии.
    • Правила противоречат друг другу: «всегда пиши тесты» и «не трогай папку tests».
    • Слишком широкие права: Bash(*) в allow — агент может удалить что угодно без вопроса.
    • Важные запреты только словами в CLAUDE.md вместо deny-правил и хуков.
    • Субагенту дали право писать файлы, хотя ему нужно только читать.
    Цикл tool use в коде — JS, TS, PHP, Python, сырой HTTP

async function runAgent(task: string, call: (m: unknown[]) => Promise<ModelResponse>): Promise<string> {
  const messages: unknown[] = [{ role: "user", content: task }];
  for (let step = 0; step < 20; step++) {
    const res = await call(messages);
    messages.push({ role: "assistant", content: res.content });
    if (res.stop_reason !== "tool_use") {
      return res.content.flatMap(b => (b.type === "text" ? [b.text] : [])).join("\n");
    }
    const results = res.content.flatMap(b => {
      if (b.type !== "tool_use") return [];
      const handler = handlers[b.name];
      try {
        if (!handler) throw new Error(`Неизвестный инструмент ${b.name}`);
        return [{ type: "tool_result", tool_use_id: b.id, content: handler(b.input) }];
      } catch (e) {
        return [{ type: "tool_result", tool_use_id: b.id, content: String(e), is_error: true }];
      }
    });
    messages.push({ role: "user", content: results });
  }
  return "Остановлено: лимит шагов";
}

    4 Тесты

    Проверьте себя

    Код писать не нужно. Где верный ответ один, он засчитывается по клику. Где написано «Отметьте все верные ответы», выберите все подходящие и нажмите «Проверить»: зачёт только при точном совпадении. Ответы сохраняются в браузере.

    Вопросы по уроку

    Агент «запустил тесты». Кто на самом деле выполнил команду?

    Модель выдаёт tool_use — запрос с именем инструмента и аргументами. Выполняет его программа вокруг модели. Поэтому именно там проверяют права и пишут логи.

    Куда записать «тесты запускаем через make test, а не через phpunit напрямую»?

    Это знание о проекте, оно нужно в каждой сессии. Файл правил читается в начале каждой сессии автоматически.

    Как надёжно запретить агенту читать .env с секретами?

    Текстовое правило — просьба к модели, её можно нарушить. Deny-правило и хук выполняет harness, модель не может их обойти.

    Зачем отдавать поиск по 30 файлам субагенту?

    Токены субагента тоже стоят денег. Выигрыш в другом: основной контекст не забивается сырыми файлами, и модель лучше держит главную задачу.

    Модель вернула ответ tool_use. Что в нём есть?

    tool_use — это просьба, а не результат. Модель пишет, что вызвать и с какими аргументами. Вывод тестов появится, только когда harness выполнит вызов и допишет ответ в историю.

    Модель ответила, и вы смотрите на stop_reason. Что верно?

    Цикл ветвится по stop_reason. max_tokens значит, что ответ упёрся в лимит: повтор того же запроса даст тот же обрезанный ответ и съест деньги. Поднимают лимит или останавливаются. Неизвестный stop_reason тоже лучше остановить, чем крутить вслепую.

    Модель вернула блок рассуждения и tool_use. Что дописать в историю перед результатом инструмента?

    Модель не помнит прошлых запросов, она видит только то, что вы прислали. tool_result ссылается на tool_use по id: если вызова нет в истории, запрос вернёт ошибку 400. Блоки рассуждения тоже возвращают как есть.

    Вы пишете свой цикл агента. Что в нём нужно, чтобы он не сломался на ровном месте?

    Модель может просить одно и то же бесконечно — без лимита цикл не кончится. Может позвать инструмент, которого нет, например deploy_to_prod, — тогда ей надо вернуть ошибку текстом, и она выберет другое. Без записи в историю модель не узнает, что произошло. А запускать команды модель не умеет вовсе.

    В settings.json: allow — Bash(git:*), deny — Bash(git push:*). Что верно?

    deny сильнее allow, порядок записи не важен. Широкое allow пропускает остальные команды git. Команда, к которой не подошло ни одно правило, не запрещена и не разрешена — агент спрашивает человека.

    Правило Bash(npm test) записано без :*. Что будет с командой npm test -- --watch?

    Без :* правило требует точного совпадения. Чтобы разрешить команду с любыми аргументами, пишут Bash(npm test:*). Запрета тоже нет — он бывает только в deny.

    Почему скил почти ничего не стоит, пока он не нужен?

    Это прогрессивное раскрытие: 30–100 токенов на описание вместо всей инструкции в каждой сессии. Когда скил загрузился, его текст тоже стоит токенов, как и всё в окне.

    Агент не находит ваш скил «новая миграция». Что стоит проверить?

    Агент выбирает скил по описанию, сравнивая его с задачей. Нет нужных слов или описание обо всём сразу — скил не сработает. Не там лежит — агент о нём не знает. Длина тела на выбор не влияет: короткий точный скил лучше длинного.

    Что из этого — ошибки в настройке агента?

    Длинный файл правил прячет важное и стоит токенов в каждой сессии. Bash(*) разрешает любую команду без вопроса, даже удаление. Ревьюеру нужно только читать. А команды сборки и тестов — как раз то, что должно лежать в файле правил.

    Какие инструменты дать субагенту-ревьюеру?

    Минимум прав — меньше риск. Ревьюер, который может писать, однажды «поправит» код сам, и это никто не проверит. Если ему нужны тесты, дайте одну точную команду, а не весь терминал.
