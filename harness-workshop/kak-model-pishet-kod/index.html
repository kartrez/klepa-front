Часть 1 · Что внутри модели · Урок 1

Как модель пишет код: токены, внимание, окно контекста и галлюцинации

Почему модель иногда пишет отличный код, а иногда уверенно выдумывает функцию, которой нет. Разберём механику без формул, а потом — с ними.

~45 минут 4 интерактива 3D-фильм и 11 вопросов Примеры: JS · TS · PHP · Python

После урока вы сможете

  • объяснить, что LLM делает «под капотом», одной фразой;
  • посчитать токены и прикинуть, сколько стоит задача агента;
  • понять, почему модель «забывает» и почему ответы каждый раз разные;
  • назвать причины галлюцинаций и три способа их снизить.

Запомните главное: модель не «ищет ответ». Она каждый раз выбирает продолжение, которое звучит правдоподобно. Правдоподобно и правильно — не одно и то же. Весь курс — про то, как построить вокруг модели среду, которая превращает правдоподобное в проверенное.

2 Объяснение

От простого к сложному

Сначала короткий фильм — 40 секунд. Он показывает один шаг модели целиком. Остановите в любой момент, перемотайте, поверните сцену мышью и кликните по деталям.

Уровень 1 · Суть

Модель — это функция «текст → следующий кусочек»

Для бэкендера проще всего думать так. LLM (большая языковая модель) — это чистая функция. На вход — текст. На выход — вероятности для следующего кусочка текста. Такой кусочек называют токеном.

Чтобы написать длинный ответ, программа вокруг модели крутит цикл: спросила модель, выбрала токен, дописала его в конец, спросила снова.

let text = "Код 404 означает, что";
while (!text.endsWith(".")) {
  const probs = model(text);      // { " ресурс": 0.61, " страница": 0.27, ... }
  const token = pick(probs);      // выбрать один токен
  text += token;                  // дописать и повторить
}

Уровень 2 · Детали

Токены, окно контекста и внимание

Токены. Модель режет текст не на буквы и не на слова, а на частые кусочки. Частое английское слово — обычно один токен. Русское слово часто режется на два-три. Поэтому одинаковый по смыслу текст на русском обычно стоит дороже. За токены платят: и за входные, и за выходные.

Окно контекста. Это весь текст, который модель видит за один вызов: системные правила, история диалога, файлы, результаты инструментов и сам ответ. У окна есть предел в токенах. Всё, что не влезло, для модели не существует.

Внимание (attention). Каждый токен «оглядывается» на остальные и решает, кто ему важен. В фразе «сервер вернул ошибку, потому что он перегружен» слово «он» больше всего смотрит на «сервер». Это и даёт модели понимание связей в тексте. Попробуете ниже в интерактиве.

Уровень 3 · Усложнение

Откуда берутся галлюцинации и нестабильность

Галлюцинация — уверенный, но неверный ответ. Причина в самой задаче модели: её учили продолжать текст правдоподобно, а не говорить правду. Если модель не знает API вашей библиотеки, правдоподобное продолжение — выдумать похожую функцию. Ответ «не знаю» в обучающих текстах встречается редко, поэтому модель его почти не выбирает.

Потеря контекста. Если важный факт выпал из окна, модели неоткуда его взять. Даже внутри окна факт в середине длинного текста модель замечает хуже, чем в начале или в конце. Это называют эффектом «потерянной середины» (lost in the middle).

Нестабильность. Следующий токен выбирается случайно, с учётом вероятностей. Поэтому один и тот же запрос даёт разные ответы. Степень случайности задаёт temperature. В новых моделях Claude этот параметр убран из API: стабильность достигают чётким форматом ответа, структурированным выводом и проверками.

Мост к следующим урокамНи одну из этих проблем не решить «правильной фразой» в запросе. Их решают инженерно: дают модели нужный контекст (уроки 2 и 3), инструменты для проверки (урок 4), автоматический контроль (урок 7) и тесты-эталоны (урок 8). Всё это вместе и называется harness — «упряжь» для модели.
Формула внимания и softmax без страха — для любопытных

Каждый токен превращается в вектор — список чисел. Из него получают три вектора:

  • Query (запрос) — «что я ищу»;
  • Key (ключ) — «что я могу предложить»;
  • Value (значение) — «что я отдам, если меня выберут».

Похоже на поиск в хеш-таблице, только нечёткий. Токен сравнивает свой Query со всеми Key (скалярное произведение), получает оценки, превращает их в веса через softmax и берёт взвешенную сумму Value.

Attention(Q, K, V) = softmax(Q · Kᵀ / √d) · V

softmax(x)ᵢ = exp(xᵢ / T) / Σ exp(xⱼ / T)     ← T — та самая temperature

Отсюда два практических вывода:

  • Каждый токен смотрит на каждый. Значит, стоимость вычислений растёт примерно как квадрат длины текста. Длинный контекст — медленно и дорого.
  • Softmax никогда не даёт ровно ноль. У любого, даже бредового продолжения есть шанс. Чем выше temperature, тем этот шанс больше.

Как температура меняет ответ, проверите в вопросах в конце урока.

Почему агент дорогой: история растёт на каждом шаге — важно для бюджета

Агент работает циклом: модель просит инструмент, программа его выполняет, результат дописывается в историю, и вся история снова уходит модели. Шаг 1 отправляет 5 тысяч токенов, шаг 10 — уже 25 тысяч, шаг 20 — 45 тысяч. Сумма растёт почти как квадрат числа шагов.

Помогают три вещи. Кэш промпта: одинаковое начало запроса (правила, описание инструментов) провайдер берёт из кэша в разы дешевле. Сжатие истории: старые шаги заменяют короткой сводкой. Субагенты: тяжёлое чтение уходит в отдельный контекст, а в основной возвращается только вывод (урок 2).

      4 Тесты

      Проверьте себя

      Код писать не нужно. Где верный ответ один, он засчитывается по клику. Где написано «Отметьте все верные ответы», выберите все подходящие и нажмите «Проверить»: зачёт только при точном совпадении. Ответы сохраняются в браузере.

      Вопросы по уроку

      Что на самом деле делает LLM, когда «отвечает» на вопрос?

      Модель — функция «текст → вероятности следующего токена». Длинный ответ получается циклом. Ни поиска, ни запуска кода внутри модели нет: это добавляет harness через инструменты.

      Вы задали модели два вопроса подряд. Откуда во втором запросе она знает про первый?

      Модель не хранит состояние. Историю каждый раз шлёт клиент. Поэтому длинный диалог дорожает с каждым сообщением.

      Агент уверенно вызвал в коде метод, которого нет в вашей библиотеке. Что поможет надёжнее всего?

      Просьба снижает частоту, но не гарантирует результат. Проверяемость даёт среда: инструмент поиска даёт факты, тесты ловят ошибку автоматически.

      Что случится с фактом, который выпал за пределы окна контекста?

      Окно — всё, что модель видит. Чтобы факты не терялись, harness сжимает историю в сводку или хранит их во внешней памяти и подставляет по запросу (урок 3).

      Что верно про токены?

      Токенизатор режет текст на частые куски. Частое английское слово — один токен, русское чаще бьётся на два-три. Лимиты и счёт идут в токенах, поэтому длинный русский текст быстрее заполняет окно и стоит дороже.

      Вы поставили температуру 0 вместо 1. Что изменится?

      Температура меняет только выбор среди кандидатов. Знаний она не добавляет. Если самый вероятный вариант — выдумка, при температуре 0 модель будет повторять эту выдумку каждый раз.

      Агент сделал 40 шагов вместо 20, а входных токенов стало почти вчетверо больше. Почему?

      Модель ничего не помнит, поэтому каждый шаг отправляет ей всё заново. Шаг 1 несёт правила и задачу, шаг 20 — ещё и 19 прошлых шагов. Сумма растёт как квадрат числа шагов. Поэтому хороший harness сжимает историю и кэширует неизменное начало.

      Что делает механизм внимания?

      Внимание раздаёт веса прошлым токенам. В фильме выше после «что» сильнее всего весит «404»: именно он решает, о чём будет продолжение. Памяти между запросами внимание не даёт.

      Важное правило проекта рискует выпасть из окна контекста. Что поможет?

      Окно ограничено, поэтому важное надо держать там постоянно, а лишнее — убирать. Файл правил подкладывается в каждый запрос, резюме экономит место, субагент читает большие файлы в своём окне. Капслок слово не закрепляет: в начале длинного диалога оно выпадет первым.

      Один и тот же запрос дал два разных ответа. Что это значит?

      На каждом шаге модель тянет токен из распределения. Первый же другой токен уводит ответ по другой дорожке. Для повторяемого результата нужны низкая температура, точная постановка и проверка тестами.

      Агент написал код. Какие признаки выдумки модели стоит проверить в первую очередь?

      Модель пишет правдоподобное, а не проверенное. Чаще всего она выдумывает имена: методы, пакеты, ключи конфига. Это ловит запуск: тесты, сборка, линтер. Форматирование тут ни при чём.

      Задание на своём проекте — 15 минут, без кода
      1. Откройте любой чат с LLM. Спросите, что делает функция из вашего рабочего проекта. Код не показывайте. Запишите ответ.
      2. Теперь вставьте код этой функции и задайте тот же вопрос. Сравните. Сколько в первом ответе было выдумано?
      3. Вставьте самый большой файл проекта в токенайзер. Сколько в нём токенов? Сколько будет стоить прочитать его на каждом из 20 шагов агента, если файл каждый раз уходит на вход заново?
      5 Чек-лист

      Отметьте, что усвоили

      • Могу одной фразой объяснить, что делает LLM: предсказывает следующий токен.
      • Знаю, что такое токен и почему русский текст обычно дороже английского.
      • Понимаю: модель не помнит прошлые запросы, историю каждый раз отправляет клиент.
      • Могу объяснить, что такое окно контекста и что бывает при переполнении.
      • Понимаю, почему «правдоподобно» не значит «правильно» и откуда галлюцинации.
      • Понимаю, почему вдвое больше шагов агента стоит почти вчетверо дороже по входу.
      • Могу назвать три способа снизить галлюцинации: дать контекст, дать инструмент проверки, проверить результат тестами.
